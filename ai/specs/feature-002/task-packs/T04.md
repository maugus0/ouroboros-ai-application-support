## Objective
Enrich `eval_results.json` with complete transparent metadata: the running model, prompt version, temperature, token usage, and latency percentiles — without incurring additional API calls.

---

## Scope

- [ ] In `run_evals.py`, after each `generate_response()` call, capture additional:
  - `model_id`: from `app/llm/openai_client.py` response or config (e.g., `gpt-4o`)
  - `temperature`: from the current config (read from env var or hardcoded in client)
  - `token_usage`: `{"prompt_tokens": N, "completion_tokens": M}` from OpenAI response `usage` field
  - `prompt_version`: run `git log --format="%h" -n 1 -- <prompt_file_path>` to get short SHA. If fail → `"unknown"`
- [ ] Calculate aggregate after running all cases:
  - `latency_p50_ms`: median of all `latency_ms` in `cases`
  - `latency_p95_ms`: 95th percentile
  - `model_id` and `judge_model_id` at top-level
- [ ] Add all fields to `eval_results.json` (top-level and per-case)
- [ ] `--dry-run` mock: `model_id = "gpt-4o-mock"`, `token_usage = {"prompt_tokens": 100, "completion_tokens": 200}`

---

## Acceptance Criteria
- [ ] `eval_results.json` after dry-run contains: `model_id`, `judge_model_id`, `latency_p50_ms`, `latency_p95_ms`
- [ ] Each case in the `cases` array contains: `prompt_version`, `temperature`, `token_usage`
- [ ] `prompt_version` is a 7-char git short SHA or `"unknown"` (does not crash)
- [ ] `latency_p50_ms` and `latency_p95_ms` are correctly calculated from the `latency_ms` array of the cases

---

## Constraints
- Do not add new dependencies — use `statistics` (stdlib) for percentile, `subprocess` for git
- Do not change scoring logic
- Backward-compatible: all fields are additive, do not delete old fields
