## Objective
Create `scripts/store_eval_baseline.py` to automatically update the GitHub repo variable `EVAL_BASELINE_SCORE` after each eval pass, and add a README summarizing how to use the LLMOps pipeline.

## Scope

### Script `scripts/store_eval_baseline.py`:
- [ ] Read `eval_results.json` (output of run_evals.py)
- [ ] Extract `avg_score` from JSON
- [ ] Use GitHub API (via `gh` CLI or `GITHUB_TOKEN`) to update repo variable `EVAL_BASELINE_SCORE`
  ```bash
  gh variable set EVAL_BASELINE_SCORE --body "$NEW_SCORE" --repo "$GITHUB_REPOSITORY"
  ```
- [ ] Print clearly: "Baseline updated: {old} → {new}"
- [ ] If `GITHUB_TOKEN` is not set → print warning and exit(0) (do not fail)
- [ ] Support `--dry-run` flag: print what would be updated without actually updating

### Integrate into `deploy.yml` (update T04 job if necessary):
- [ ] After `llm-eval` pass, add step to call `store_eval_baseline.py` with `GITHUB_TOKEN`
  ```yaml
  - name: Update eval baseline
    if: success()
    env:
      GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    run: python scripts/store_eval_baseline.py
  ```
- [ ] Need to add `variables: write` to permissions of `llm-eval` job

### Documentation `ai/specs/feature-001/README.md`:
- [ ] Create `ai/specs/feature-001/README.md` summarizing:
  - Purpose of the feature
  - How to run prompt-lint locally
  - How to run eval locally (dry-run vs real)
  - How to reset baseline manually (when intentionally changing prompts)
  - Troubleshooting: llm-eval being skipped, baseline drift, flaky judge
