## Objective
Tạo bộ golden test fixtures (JSON) cho eval — các cặp `{input, evaluation_criteria}` đại diện cho các use case thực tế của user.

## Scope
- [ ] Tạo `tests/llm/fixtures/sop_golden_cases.json` với **5 test cases** gồm:
  - Mỗi case: `id`, `description`, `input` (context dict gửi vào LLM), `evaluation_criteria` (rubric string cho judge)
  - Case đa dạng: sinh viên STEM, Humanities, MBA, PhD research, career change
- [ ] Tạo `tests/llm/fixtures/cover_letter_golden.json` với **3 test cases**
- [ ] Tạo `tests/llm/fixtures/judge_rubric.json` — rubric chung cho LLM-as-judge:
  ```json
  {
    "sop": {
      "rubric": "Score 1-10: Structure(3pts) + Relevance(3pts) + No-hallucination(2pts) + Tone(2pts)",
      "min_passing_score": 6.0
    },
    "cover_letter": {
      "rubric": "Score 1-10: Opening(2pts) + Fit(3pts) + Specific-examples(3pts) + CTA(2pts)",
      "min_passing_score": 6.0
    }
  }
  ```

### Format của mỗi golden case:
```json
{
  "id": "sop-001",
  "description": "STEM PhD applicant, strong research background",
  "operation": "sop_generate",
  "input": {
    "student_name": "...",
    "target_program": "...",
    "university": "...",
    "degree_level": "phd",
    "field_of_study": "...",
    "research_interests": "...",
    "relevant_experience": "...",
    "academic_achievements": "...",
    "career_goals": "..."
  },
  "evaluation_criteria": "The SOP should mention research background clearly, align with PhD program goals, avoid generic statements"
}
```

## Out of Scope
- Không gọi LLM để tạo fixture (tạo thủ công hoặc dùng data thực)
- Không tạo fixtures cho checklist hay deadline service
- Không tạo fixtures cho edge cases (error handling) — chỉ happy path

## Acceptance Criteria
- [ ] `tests/llm/fixtures/sop_golden_cases.json` có đúng 5 cases, valid JSON
- [ ] `tests/llm/fixtures/cover_letter_golden.json` có đúng 3 cases, valid JSON
- [ ] `tests/llm/fixtures/judge_rubric.json` có rubric cho `sop` và `cover_letter`
- [ ] Tất cả `input` fields match với actual service input schema (test bằng Pydantic validation)
- [ ] `description` field của mỗi case đủ rõ để reviewer hiểu không cần đọc `input`

## Constraints
- Không dùng PII thật (dùng fake names, fake universities nếu cần)
- Giữ input ngắn gọn (~200-500 words) để tránh tốn tokens trong eval
- Không sửa bất kỳ file nào ngoài `tests/llm/fixtures/`
